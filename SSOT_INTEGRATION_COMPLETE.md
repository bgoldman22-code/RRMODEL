# SSOT Integration Complete - NFL Receiving Props Scanner

**Status**: ✅ COMPLETE  
**Date**: October 18, 2025  
**Feature**: SSOT (Single Source of Truth) wired into Elite Production Scanner

---

## 🎯 What Changed

### **Scanner Enhancement** (`nfl-receiving-scanner-elite.mjs`)
- Added `loadSSOT` and `playerToParams` imports
- Feature flag: `USE_SSOT` environment variable
- Dual-mode operation: SSOT (production) or PLAYER_DB (legacy)
- Automatic fallback: If SSOT load fails, scanner uses PLAYER_DB
- Matchup display: Now pulls from SSOT `matchup` field (e.g., "NE @ TEN")
- Data source tracking: All opportunities tagged with `data_source` field

---

## 🔧 Architecture

### **Data Flow (SSOT Mode)**
```
nflfastR PBP + Canonical Rosters
         ↓
  generate-ssot.R (R script)
         ↓
  data/nfl/ssot/week_8_2025.json
         ↓
  loadSSOT() (ssot-loader.mjs)
         ↓
  playerToParams() (applies modifiers)
         ↓
  Elite Pricing Engine (cascade simulation)
         ↓
  Scanner Output (opportunities with edges)
```

### **Data Flow (Legacy Mode)**
```
PLAYER_DB (hardcoded)
         ↓
  estimateParameters() (elite-pricing-engine.mjs)
         ↓
  Elite Pricing Engine (cascade simulation)
         ↓
  Scanner Output (opportunities with edges)
```

## 🎯 Key Features

### **1. Dual-Mode Operation**
- **SSOT Mode**: Production-grade data from nflfastR + canonical rosters
- **Legacy Mode**: Hardcoded PLAYER_DB for rapid development/testing
- **Automatic Fallback**: If SSOT fails, scanner gracefully degrades to PLAYER_DB

### **2. Matchup Display**
- **Before**: `"DAL vs OPP"` (generic)
- **After**: `"DAL @ NYG"` (actual opponent from schedule)
- **Source**: SSOT JSON `matchup` field (generated by R script)

### **3. Data Provenance**
- Every opportunity tagged with `data_source: "SSOT"` or `"PLAYER_DB"`
- Metadata includes SSOT generation timestamp + week/season
- Enables A/B testing (compare SSOT vs PLAYER_DB predictions)

### **4. Current Team Assignments**
- **Before**: Stefon Diggs shows HOU (historical PBP team)
- **After**: Stefon Diggs shows NE (current team from canonical rosters)
- **How**: SSOT uses canonical rosters to override historical PBP teams

### **5. Opponent Defense Adjustments**
- SSOT includes per-ADOT-bucket opponent modifiers
- `playerToParams` applies modifiers via Beta mean-shifting (not concentration scaling)
- Per-dropback normalization removes pace bias (fast teams don't look soft)

## 🐛 Troubleshooting

### **SSOT Load Fails**
```
⚠️  Could not load SSOT: ENOENT: no such file or directory
⚠️  SSOT load failed, falling back to PLAYER_DB
```
**Solution**: Run `Rscript scripts/nfl-receiving-props/generate-ssot.R` to generate SSOT file

### **Schema Version Mismatch**
```
⚠️  Could not load SSOT: Unsupported SSOT schema version: 2
⚠️  SSOT load failed, falling back to PLAYER_DB
```
**Solution**: Update scanner to support new schema version or regenerate SSOT with correct version

### **Player Name Mismatch**
```
ℹ️  Unknown market key: player_receiving_yards
```
**Solution**: Check `MARKET_ALIASES` includes all API variants, verify `canon()` normalization works

### **Missing Matchup**
```json
{ "matchup": "DAL vs OPP" }  // ❌ Wrong - should show opponent
```
**Solution**: Verify SSOT JSON includes `matchup` field, check schedule join in R script
