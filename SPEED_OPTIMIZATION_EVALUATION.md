## 📊 Speed Plan Evaluation

### ✅ Recommendation #1: HTTP Caching Headers
**Status**: **CRITICAL - Implement immediately**

**Current**:
```javascript
// nfl-predictions-get/index.cjs
return { statusCode: 200, body: JSON.stringify(predictionData) };
// Headers: cache-control: no-cache (Netlify default)
```

**Proposed**:
```javascript
const etag = '"' + crypto.createHash('md5').update(body).digest('hex').slice(0, 16) + '"';

if (event.headers['if-none-match'] === etag) {
  return { statusCode: 304, headers: { ETag: etag } };
}

return {
  statusCode: 200,
  headers: {
    'Content-Type': 'application/json',
    'Cache-Control': 'public, max-age=60, stale-while-revalidate=1800',
    'ETag': etag,
    'Last-Modified': new Date().toUTCString()
  },
  body
};
```

**Impact**:
- ✅ **60-90% TTFB reduction** on repeat visits (304 responses ~50-100ms)
- ✅ Browser/CDN can cache for 1 minute, serve stale for 30min while revalidating
- ✅ Zero code complexity (just headers)
- ✅ Works immediately with existing refresh cadence (30min)

**Risk**: None. Backwards compatible, graceful degradation.

### ⚠️ Recommendation #4: Parallel I/O + Timeouts in Generate
**Status**: **EVALUATE - May not be needed**

**Current Generate Flow** (from code inspection):
```javascript
// Line 3217: Auto-fetch schedule
const scheduleRes = await fetch('nfl-schedule-get');

// Line 2240-2260: Load data sequentially
const teamData = await loadAdvancedMetrics(season, week);
const injuryData = await loadInjuries(season, week);
const oddsData = await loadOdds();
```

**Proposed**:
```javascript
const withTimeout = (p, ms=3500) =>
  Promise.race([p, new Promise((_, reject) => 
    setTimeout(() => reject(new Error('timeout')), ms))]);

const [schedule, teamData, injuryData, oddsData] = await Promise.allSettled([
  withTimeout(fetch('nfl-schedule-get').then(r => r.json())),
  withTimeout(loadAdvancedMetrics(season, week)),
  withTimeout(loadInjuries(season, week)),
  withTimeout(loadOdds())
]).then(results => results.map((r, i) => {
  if (r.status === 'fulfilled') return r.value;
  console.warn(`[${['schedule','team','injury','odds'][i]}] Load failed, using fallback`);
  return loadLastKnownGood(i);
}));
```

**Impact**:
- ✅ **2-3x faster** if sources can be parallelized
- ✅ **Resilience** to slow/failing APIs
- ⚠️ **Complexity**: Need last-known-good fallbacks

**Evaluation**:
- **Wait**: Generate runs every 30min scheduled, not on-demand
- **Users hit GET** (already fast blob read), not generate
- **Benefit**: More reliable scheduled runs, but doesn't affect TTFB for users
- **Verdict**: Nice-to-have for reliability, but **low priority for speed**

### ✅ Recommendation #5: Client-Side SWR (Stale-While-Revalidate)
**Status**: **IMPLEMENT with HTTP caching**

**Current**: Frontend fetches on every page load, waits for response

**Proposed**:
```javascript
// predictions-client.js
const CACHE_KEY = 'nfl_predictions_v1';
const CACHE_TTL = 60 * 1000; // 1 minute

async function loadPredictions() {
  // 1. Show cached immediately (if fresh)
  const cached = localStorage.getItem(CACHE_KEY);
  const cachedTime = localStorage.getItem(CACHE_KEY + '_time');
  
  if (cached && cachedTime && (Date.now() - cachedTime < CACHE_TTL)) {
    renderPredictions(JSON.parse(cached));
    return; // Still fresh, skip fetch
  }
  
  // 2. Show stale cache while fetching
  if (cached) {
    renderPredictions(JSON.parse(cached));
  } else {
    showLoadingSpinner();
  }
  
  // 3. Fetch in background (with ETag support)
  try {
    const response = await fetch('/.netlify/functions/nfl-predictions-get', {
      headers: cached ? { 'If-None-Match': localStorage.getItem(CACHE_KEY + '_etag') } : {}
    });
    
    if (response.status === 304) {
      // Still valid, just update timestamp
      localStorage.setItem(CACHE_KEY + '_time', Date.now());
      return;
    }
    
    if (response.ok) {
      const data = await response.json();
      localStorage.setItem(CACHE_KEY, JSON.stringify(data));
      localStorage.setItem(CACHE_KEY + '_time', Date.now());
      localStorage.setItem(CACHE_KEY + '_etag', response.headers.get('ETag'));
      renderPredictions(data);
    }
  } catch (error) {
    // If network fails and we have stale cache, keep showing it
    if (!cached) showError();
  }
}
```

**Impact**:
- ✅ **Instant first paint** from localStorage
- ✅ **Background refresh** (user never sees spinner after first visit)
- ✅ **Works offline** (shows last cached data)
- ✅ **Handles 304s** gracefully

**Risk**: None. Progressive enhancement.

## ⚠️ Risks & Mitigations

### Risk 1: Stale Data Shown to Users
**Scenario**: User sees 30-min-old predictions

**Mitigation**:
- ✅ Show "Updated X min ago" timestamp
- ✅ `stale-while-revalidate=1800` (30min) matches refresh cadence
- ✅ Background refresh keeps cache fresh
- ✅ Manual refresh button triggers new generation

### Risk 2: ETag Collision
**Scenario**: Two different payloads generate same ETag

**Mitigation**:
- ✅ Use MD5 hash (collision rate: 1 in 10^38)
- ✅ Include generation timestamp in blob metadata
- ✅ ETags are cache hints, not security (collisions just cause extra download)

### Risk 3: localStorage Quota Exceeded
**Scenario**: 28KB predictions + other data exceeds 5-10MB quota

**Mitigation**:
- ✅ Try/catch localStorage operations
- ✅ Fallback to in-memory cache
- ✅ Clear old cache versions on error

### Risk 4: Browser Cache Poisoning
**Scenario**: Bad predictions cached for 60s

**Mitigation**:
- ✅ Short max-age (60s) limits blast radius
- ✅ Scheduled refresh ensures fresh data every 30min
- ✅ Hard refresh (Ctrl+Shift+R) bypasses cache
- ✅ Can invalidate by changing ETag in generate function
